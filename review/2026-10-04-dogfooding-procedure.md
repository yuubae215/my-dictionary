# dogfooding 手順（2026-10-04）

対象：`pilot/` 全8ファイル（STD-EED-0001-0〜5、-C、-M）。
位置づけ：原辞書の全章の変換と、設計レビュー（`review/2026-09-05-design-review.md`）が残した判断待ち5件の裁定が終わった時点で、次に行う検証の手順を定める。
本ファイルは手順書であり、実施結果は別ファイル（§6）に記録する。

---

## 1. 目的

本仕様書はこれまで、原辞書と仕様書自身だけを材料に検証してきた。
部ごとの変換は**概念ドリフト**（名前と定義文のズレ）を、全編化は**集計ドリフト**（エントリの増減が集計に反映されないこと）を検出したが、どちらも辞書の内側の整合を確かめたにすぎない。
`backlog.md` §1 が記すとおり、判断待ちは0件であり、新しい判断の材料は辞書の外側からしか入ってこない。

**dogfooding**：本仕様書の語彙を使って、辞書の外にある実在の文書を読み解き、辞書が実務で引けるかを確かめる作業。

本手順では、1本の実文書に出てくる空間語をすべて EED-ID に結びつけ、結びつかなかった語を分類して起票する。
これによって次の4つの仮説を検証する。

| ID | 仮説 | 反証となる観察 |
| :--- | :--- | :--- |
| H1 | 第2編3.18 方向参照枠と3.19 離散姿勢区分があれば、方向語（右、左、手前、奥、上流、下流、表、裏）の「誰から見て」を決められる | 方向語の出現のうち、参照枠を内在的、相対的、絶対的のどれにも割り当てられないものがある |
| H2 | 現場語は（語, 主語）の組で一意に代表形へ引ける（全編附属書A） | 同じ（語, 主語）の組が、文脈によって別の代表形を指す |
| H3 | 新設、分割、統合の3段判定（`decisions.md` 冒頭）は、辞書の書き手以外も同じ結論に到達できる | 同じ未収録語に対し、実施者と書き手で止まる段が食い違う |
| H4 | 提案値 P-01〜P-08 は実文書の記述に必要である | 提案値のエントリが、実文書の読解で1度も引かれない |

H4 は承認の材料を集める目的を兼ねる。
たとえば P-06 の現場語 `eed:0154`〜`0159`（右、左、手前、奥、上流、下流）は原辞書に記載がなく「存在確認前」のまま登録されている。
実文書にこれらの語が主語つきで現れれば、それが存在確認の記録になる。

## 2. 実施しないこと

- `source/` を編集しない。原辞書への指摘は従来どおり `backlog.md` §3 に F- 項目として登録する。
- dogfooding の途中で `pilot/` を書き換えない。読解中に辞書を直すと、どの観察がどの版の辞書に対するものかが分からなくなる。修正は §5 の起票を経て、`decisions.md` に判断を記録してから行う（README「変換の進め方」6・7 と同じ規則）。
- 対象文書の原文をリポジトリに置かない。社内文書を想定しているため、記録には出現箇所（節番号、行番号）と、判定に必要な最小限の抜粋だけを書く。製品名、顧客名、図番は伏せる。

## 3. 対象文書の選び方

1本目は次の4条件をすべて満たす文書から選ぶ。

1. 実在し、実務で使われた（または使われている）文書である。dogfooding のために書き下ろした文書は、書き手が辞書の語彙に寄せてしまうため対象にしない。
2. 空間語（方向、位置、姿勢、座標系、原点、基準に関わる語）を少なくとも30箇所程度含む。少なすぎると判定の分布が取れない。
3. 0章の4ドメイン（設計、生技、制御、情報）のうち2つ以上が読み手または書き手として関わっている。ドメインをまたがない文書では、視点依存による取り違えが起きにくい。
4. 版と日付を特定できる。記録が参照する文面を後から固定できるようにするためである。

条件を満たす候補を、H1 を直接試せる順に並べると次のようになる。

| 優先 | 文書の種類 | 主に試せる仮説 | 理由 |
| ---: | :--- | :--- | :--- |
| 1 | 方向や原点の取り違えが原因になった不具合報告、是正報告 | H1、H2 | 辞書の動機（「右と言っても誰から見て右か」）そのものの事例であり、取り違えが本当に解消できたかを事後に判定できる |
| 2 | 装置仕様書、セル仕様書（レイアウト図の説明文を含む） | H1、H4 | 架台、装置ボディ、カメラの3種の座標系（第2編 Clause 4）と、正面、上流側といった方向語が同じ文書に並ぶ |
| 3 | ロボットのティーチング指示書、段取り替え手順書 | H1、H2 | 作業者の立ち位置を基準にした相対的枠の語が多い。「原点」「姿勢」の同音異義も出やすい |
| 4 | CAD から下流（PLC、MES、ビジョン）へのデータ交換仕様 | H2、H4 | 第C編3.1 公開言語（P-08）と、ハンドネス、尺度定義、回転表現規約（P-07）の出番がある |

2本目以降は、1本目と別の種類の文書を選ぶ。
同じ種類を続けると、文書の書式に由来する偏りと辞書の欠落を区別できない。

## 4. 手順

### 4.1 準備

1. 対象文書の版と日付を記録ファイル（§6）の冒頭に書く。
2. 実施時点のリポジトリのコミットハッシュを同じく冒頭に書く。判定はこの版の `pilot/` に対して行う。
3. 実施者を決める。可能なら、辞書の書き手ではない人を1人含める（H3 のため）。2人で実施する場合、§4.2〜§4.5 は互いの結果を見ずに独立に行う。

### 4.2 空間語の抽出

対象文書から、空間に関わる語句の**出現**をすべて抜き出し、1出現を1行として記録する。
同じ語が10回出れば10行になる。
語ごとではなく出現ごとに数えるのは、同じ語が段落によって別の主語を取る（H2 の反証になる）場合を拾うためである。

抽出漏れを減らすため、次の2つを併用する。

- 機械的な抽出：全編附属書A の現場語と同義、異表記の列、附属書G.1、G.2 の見出し語で文書を検索する。
- 目視での抽出：方向語（右、左、前、後、手前、奥、上、下、上流、下流、表、裏、正、逆、正面、背面、内側、外側）と、数値に単位や軸名が付いた記述（「X+50」「90度回転」など）を拾う。方向語は辞書に未登録のものが多いため、検索だけでは漏れる。

### 4.3 主語の特定

各出現について、その語が**誰について**言われているかを全編附属書D の登場人物20件から選ぶ。
主語は、文書の書き手ではなく、語が指す実在物である。
たとえば作業者が書いた手順書の「ワークの表」の主語は作業者ではなくワークである。

文書から主語を1つに決められない場合は、候補をすべて書き、判定を M3（§4.5）とする。
主語が決まらないこと自体が、文書の側の曖昧さを辞書が検出した結果にあたる。

### 4.4 代表形への対応づけ

1. （語, 主語）の組で全編附属書A を引き、代表形の EED-ID を得る。
2. 附属書A に組がない場合は、附属書G.1、G.2 から概念を直接探す。
3. 方向語については、加えて第2編3.18 の3種の参照枠（内在的、相対的、絶対的）のどれで解釈されているかを書く。文書の文面から決まらなければ「不定」と書く。
4. 得た代表形の定義文を読み、文書中の用法と一致するかを確かめる。名前の一致だけで対応づけを済ませない。

### 4.5 判定

各出現を次の6区分のどれか1つに判定する。

| 区分 | 状況 | 次の作業 |
| :--- | :--- | :--- |
| **M1 一致** | （語, 主語）が附属書A にあり、文書中の意味が代表形の定義文と一致する | なし |
| **M2 概念のみ** | 概念はあるが、（語, 主語）の組が附属書A に未登録 | 現場語の追加候補として記録（§5） |
| **M3 主語不定** | 文書から主語、または方向語の参照枠が1つに決まらない | 文書側の曖昧さとして記録。辞書の不備ではない |
| **M4 複数候補** | 主語は決まるが、代表形の候補が2つ以上残る | 同音異義の未登録か、定義文どうしの境界が不明確かを切り分ける |
| **M5 不一致** | （語, 主語）は登録されているが、文書中の意味が代表形の定義文と違う | 現場語の誤登録か概念ドリフトかを切り分ける |
| **M6 該当なし** | 対応する概念が辞書にない | §4.6 の3段判定へ |

M3 と M4 は混同しやすい。
M3 は「文書を書き直せば解消する」もの、M4 は「辞書を直さないと解消しない」ものである。
判定に迷った場合は、文書の書き手に主語を確認できるかを基準にする。
確認すれば決まるなら M3、確認しても候補が残るなら M4 とする。

### 4.6 未収録語への3段判定

M6 の語（同じ語が複数回出ても1件として扱う）に、`decisions.md` 冒頭の3段判定を適用する。
記録には結論だけでなく、どの段で止まったか、または3段すべてを通ったかを書く。

2人で実施している場合は、両者の結果を突き合わせる前に各自の判定を確定させる。
止まった段が食い違った件数が H3 の観察になる。

### 4.7 突き合わせ（2人で実施した場合）

§4.3〜§4.5 の結果を出現ごとに突き合わせ、主語、代表形、区分のそれぞれで一致率を出す。
主語が一致しているのに代表形が食い違う出現は、H2 の反証候補として個別に検討する。
一致率の目標値は1本目では置かない。
比較の基準が無いまま閾値を決めても根拠を示せないため、1本目の値を2本目以降の基準とする。

## 5. 起票

判定結果は、既存の台帳の規則に従って起票する。
dogfooding 用の新しい台帳は作らない。

| 判定 | 起票先 | 内容 |
| :--- | :--- | :--- |
| M1 のうち P- 項目のエントリを引いたもの | `backlog.md` §2 の該当 P- 行 | 「確定に必要なこと」欄に、実文書での使用実績（記録ファイル名と出現数）を追記する。P-06 の方向語は存在確認の記録になる |
| M2 | `backlog.md` §2（P-06 と同じ扱いの新しい P- 項目） | 現場語の追加候補。存在確認済みとして登録できる |
| M3 | 記録ファイルのみ | 辞書の不備ではないため台帳には載せない。件数は §7 の集計に使う |
| M4、M5 | `decisions.md` に D- 項目、先送りなら `backlog.md` §1 に B- 項目 | 同音異義の追加、定義文の境界の是正、現場語の付け替えなど |
| M6 で3段を通ったもの | `decisions.md` に D- 項目、`backlog.md` §2 に P- 項目 | 新設提案。採番は README「変換の進め方」に従う |
| M6 で途中の段で止まったもの | `decisions.md` に D- 項目 | 立てない判断の記録。止まった段と理由を書く |
| 原辞書側の不備に由来するもの | `backlog.md` §3 に F- 項目 | 従来どおり |

D- 項目の採番は実施日で行う（例：D-2026-10-xx-01）。
各 D- 項目には、根拠として記録ファイル名と出現番号を書く。

## 6. 記録ファイル

記録は `review/dogfooding/` に、1文書につき1ファイルとして置く。
ファイル名は `YYYY-MM-DD-<文書の種類>.md` とする（例：`2026-10-10-cell-spec.md`）。
文書の種類だけを書き、製品名や案件名はファイル名に入れない。

記録ファイルの書式は次のとおりとする。

```markdown
# dogfooding 記録：<文書の種類>（YYYY-MM-DD）

- 対象文書：<種類>、版 <版>、日付 <日付>（原文はリポジトリ外。保管場所：<場所>）
- 辞書の版：コミット <ハッシュ>
- 実施者：<A>（書き手）、<B>（書き手以外）

## 出現一覧

| # | 箇所 | 語 | 主語（附属書D #） | 参照枠 | 代表形 EED-ID | 区分 | メモ、起票ID |
| ---: | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 3.2節 2行目 | 右 | 19 作業者 | 相対的 | `eed:0154#001` | M1 | P-06 存在確認 |
| 2 | 3.2節 5行目 | 原点 | 3 治具／18 CAD | 不定 | — | M3 | 書き手に確認中 |

## 3段判定（M6）

| 語 | 第1段 | 第2段 | 第3段 | 結論 | 起票ID |
| :--- | :--- | :--- | :--- | :--- | :--- |

## 集計

（§7 の表）
```

## 7. 集計と読み方

1本ごとに次を集計し、記録ファイルの末尾に書く。

| 指標 | 計算 | 対応する仮説 |
| :--- | :--- | :--- |
| 区分別の件数と比率 | M1〜M6 の件数 ÷ 全出現数 | 全体 |
| 方向語の参照枠決定率 | 参照枠が「不定」でない方向語の出現 ÷ 方向語の全出現 | H1 |
| M3 の内訳 | M3 のうち主語が不定のものと参照枠が不定のものの件数 | H1 |
| （語, 主語）の多義件数 | 同じ（語, 主語）の組が2つ以上の代表形を指した組の数 | H2 |
| 3段判定の一致率 | 止まった段が一致した M6 の語 ÷ M6 の語の数（2人実施時） | H3 |
| 提案値の使用数 | P-01〜P-08 のエントリごとの M1 件数 | H4 |

結果を読むときは、次の区別を守る。

- M3 の比率が高いことは、辞書の失敗を意味しない。文書が主語や参照枠を省いて書かれている度合いを示す。M3 が辞書の失敗にあたるのは、文書の書き手に確認しても、辞書の3種の参照枠のどれにも当てはまらない場合に限る。その場合は H1 の反証として M4 か M6 に判定し直す。
- M2 が多いことは、現場語の登録が追いついていないことを示し、概念体系の不備ではない。
- M5 と M4 は、変換時の概念ドリフト検出率（59件中3件、5.1%）と比較できる。比較する場合、母数が出現数ではなく概念数であることに注意し、M4、M5 を起こした概念の種類数で割る。

2本目以降は、1本目と同じ表を並べて変化を見る。
1本の結果だけで仮説の成否を結論づけない。
特に H1 は、優先1の不具合報告と優先3の手順書の両方で観察してから判断する。

## 8. 1本目の終了条件

次の3つがそろった時点で1本目を終える。

1. §4.2 で抽出した全出現に区分が付いている。
2. M2、M4、M5、M6 のすべてに起票ID（§5）が付いているか、M3 として記録だけで済ませた理由が書かれている。
3. §7 の集計表が記録ファイルにあり、README の「進捗」に1行追加されている。
