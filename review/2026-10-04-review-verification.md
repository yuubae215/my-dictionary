## 1. V-1 関係型の追加候補（レビュー §2.4）

### 1.1 判定基準

全編附属書C.4 は、新しい関係型の導入を検討する条件として次の**両方**を求める。

1. 定義文のレベルで根拠がある。
2. その概念の**すべての個体**について成立する。

レビューは3型について「既に定義文レベルで根拠がある」と述べたが、条件2は検証していなかった（C.4 はレビューの前日に B-08 の裁定とともに定まった基準であり、レビューはこれを引用しているが当てていない）。

### 1.2 `expressed-in`（値 → 参照座標系）

種別が value の第2編エントリ（3.5 姿勢、3.12 同次変換行列、3.17 アプローチ方向）と第1編3.4 安定姿勢の定義文には、どれも参照座標系が現れない。**条件1を満たす value のエントリは0件である。**

定義文に参照座標系が現れるのは 3.7 座標空間・3.8 ローカル空間（object）と 3.13 座標変換（operation）である。3.13 は既に `transforms 3.8 → 3.9` を持ち、3.8 は `is-a 3.7` から 3.7 の関係を継承する。残るのは 3.7 → 3.2 の1本だが、これは「値がある座標系で表される」関係ではなく「空間が基準の選択で定まる」関係であり、レビューの提案した型ではない。

最も自然な候補は「3.5 姿勢 expressed-in 3.7 座標空間」である。3.7 の定義文は「位置・姿勢の値を表現する基準として…」と姿勢を名指ししており、条件1は 3.7 の側で満たす。しかし条件2で止まる。D-2026-09-05-09 は姿勢を**状態**と読み、「その数値表現が座標空間の選択に依存する」と整理した（第2編3.5 Note 3）。座標空間で表されるのは姿勢の**数値表現**であって、姿勢という概念の個体（状態）ではない。

**判定：不成立。** D-2026-09-05-09 で定義文を ISO 8373 に揃えたことが、この型を構造的に締め出している。再検討するのは、姿勢の数値表現を受けるエントリ（例：「姿勢値」）を立てる判断が別途下りたときに限る。

### 1.3 `governed-by`（値 → 規約）

レビューが挙げた規約は第2編3.4 尺度定義・3.6 回転表現規約・3.11 距離定義規約の3件である。

| 規約 | 候補（現在 refers-to） | 条件1 | 条件2 | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| 3.11 距離定義規約 | 3.5 姿勢、第4編3.3 計測 | ○（3.11 の定義文が「距離を数値として扱う場面」を画定） | ×：姿勢の個体の多くは距離を伴わない。計測の個体には角度・面積もあり、距離に限られない | 不成立 |
| 3.6 回転表現規約 | 3.5 姿勢 | ○（3.6 の定義文が「姿勢が一意に定まらない」と姿勢を名指し） | ×：§1.2 と同じ理由。規約が縛るのは姿勢の数値表現であり、状態としての姿勢ではない | 不成立 |
| 3.6 回転表現規約 | 3.12 同次変換行列 | △ | —：同次変換行列は定義文で回転行列という形式を固定しており、3.6 が解消する曖昧さ（回転順序、内因性／外因性）を持たない。規約に従う値というより、規約の取りうる値の1つである | 不成立 |
| 3.4 尺度定義 | 3.12 同次変換行列 | ○（3.4 の定義文「モデル内部で扱う数値が、どの物理単位を1として表現されているか」、3.12 の定義文「並進ベクトル」） | ○：すべての同次変換行列は長さの次元を持つ並進成分を含む | **成立** |
| 3.4 尺度定義 | 3.2 参照座標系 | ○（3.2 の定義文「相対的な位置と向きによって定義される」） | ○：すべての参照座標系は親からの並進量を持つ | **成立** |

尺度定義だけが成立するのは、定義文の対象が「モデル内部で扱う数値」全般であり、表現形式の選択（3.6）や測り方の選択（3.11）のように個体によって適用の有無が分かれる規約ではないためである。

ただし採用には次の論点が残る。

- 第2編3.4 Note 3 は「単位系そのものの規定は Clause 4 が担う。本エントリは…規約を守れているかを検証・変換する運用側の責務を指す」と書く。値を実際に縛っているのは Clause 4（規定）であり、3.4（運用の考え方）ではない。`governed-by 3.4` は「規定に縛られる」ではなく「検証の対象になる」と読まれるおそれがある。
- 成立するのは2本（未接続の第1編3.3 質量特性・3.5 分解能を加えても4本）であり、既存の `constrained-by`・`transforms`（各2件）と同程度の使用数になる。

**判定：提案どおりの「値 → 規約」としては不成立。3.4 に限れば2条件を満たすが、採否は判断を要する。** `backlog.md` B-14 に登録した。

### 1.4 `evaluated-against`（値 → 期待値・レベル）

| 相手 | 候補 | 条件1 | 条件2 | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| 第3編3.13 検証レベル | 3.1 値、3.2 入力値、3.3 算出値 | ○（3.13 の定義文「あるデータが…検証されたものか」） | ×：識別子・リビジョンなど、検証レベルを持たない値が多い。EXAMPLE も把持目標姿勢・搬送安定姿勢に限っている | 不成立 |

## 3. V-4 方向語の現場語（P-06）

### 3.1 公開資料での用法

| 語 | 確認できたこと | 出典 |
| :--- | :--- | :--- |
| 上流・下流 | コンベアラインの最初のゾーンを最上流、最後を最下流と呼ぶ用法、製品の流れ方向を基準にする用法を確認した | SEW-EURODRIVE「Product flow direction」ほか |
| 右・左 | 一般語。作業者基準の用法は手順書で普遍的だが、特定の公開資料は取っていない | — |
| 手前・奥 | 工作機械の名称用語は JIS B 0105:2012 にあるが、本文は入手できなかった | — |

上流・下流は業界一般の用法として存在する。ただし P-06 が求める「存在確認」は、原辞書の運用方針（存在しない現場語を創作しない）に照らした**現場での使用実績**であり、公開資料の用例では代えられない。P-06 は存在確認前のまま据え置く。

### 3.2 手前・奥の参照枠が辞書内で食い違っている

| 箇所 | 手前・奥の参照枠 |
| :--- | :--- |
| 第2編 附属書A `eed:0156`・`0157` | **内在的枠**（主語＝工作機械。「機械の正面（操作側）に近い側」） |
| 第2編3.18 Note 4 | 「相対的枠の語（右・左・**手前・奥**）を用いるときは、主語を添える」 |
| 第2編 Clause 4「方向語の参照枠」行 | 「相対的枠（作業者から見た右・左・**手前・奥**）は数値データに用いない」 |

同じ編の中で、手前・奥が内在的枠と相対的枠の両方に分類されている。dogfooding 手順の仮説 H1（3種の参照枠で「誰から見て」を決められる）を試す前に、辞書の側で決まっていない。

日本語の「手前」は語彙としては話者基準（相対的）であり、「機械の手前」が内在的に読めるのは、作業者の立ち位置が機械の正面に固定されている場合に限られる。附属書A の登録は「工作機械」を主語に取ることでこの条件を暗黙に置いている。どちらに揃えるか（あるいは「手前」を（手前, 作業者）と（手前, 工作機械）の同音異義として2件登録するか）は判断を要する。`backlog.md` B-15 に登録した。

付記：上流・下流を絶対的枠とする分類は、ラインの流れ方向が環境に固定されている限り妥当である。可逆コンベアのように流れ方向が運転で反転する設備では、上流・下流は設備の内在的な向きに依存する。これは B-15 と同時に検討する。

## 4. V-5 Clause 4 のワールド座標系

ROS REP-103 は、ボディフレームを x 前方・y 左・z 上、地理的な位置の短距離直交表現を ENU（x 東・y 北・z 上）、カメラの `_optical` フレームを z 前方・x 右・y 下と定める。レビュー §1.1 の記述と一致する。

一方、第2編 Clause 4 のワールド座標系の行は「+X ＝ 生産ラインの流れ方向」と定めたうえで、備考欄に「ROS REP-103 のワールドフレーム（ENU）に対応」と書いている。+X をラインの流れ方向に取った時点で、ラインが東を向いていない限り ENU とは一致しない。共通なのは「環境に固定され Z が上」という点だけである。

**判定：備考欄の「対応」は不正確。** 「ENU と同じく環境に固定され Z 上だが、+X の向きは ENU（東）と異なる」と是正した（D-2026-10-04-04）。+X をラインの流れ方向とするか東とするかの提案値（F-22）そのものは変更しない。

## 5. V-6 レビューが典拠にした外部規格の記述

規格本文の多くは有償であり、ネットワーク制限で規格団体のサイトにも直接アクセスできなかった。判定は公開されている二次資料による。

| レビュー箇所 | 記述 | 判定 | 根拠 |
| :--- | :--- | :--- | :--- |
| §1.1 | REP-103 はボディ（x 前方・y 左・z 上）、ENU、光学（z 前方・x 右・y 下）を区別する | **支持** | REP-103 本文（reps.openrobotics.org） |
| §1.2 | 方向表現の参照枠は内在的・相対的・絶対的の3種（Levinson 2003） | **支持** | Cambridge University Press の書誌・章構成、LINGUIST List の書評 |
| §1.5・§1.6 | ISO 8373 の pose は「位置と向きの組み合わせ」で、参照座標系を含まない | **支持（二次資料）** | 定義文「combination of position and orientation in space」を引用する特許・教材。第2編3.5 Note 3 の「ISO 8373:2021 と同一」も、genus を「状態」とした点を除けば一致する |

| §2.1 | ISO 10241-1 の admitted term は同一概念の同義語 | **支持（二次資料）** | admitted term は preferred term に加えて同じ概念に用いてよい語として扱われる（JATS term-status、Glossarist concept model） |
| §2.2 | Directives Part 2 は「定義は要件の形をとってはならず、要件を含んではならない」と定める | **支持** | ISO/IEC Directives Part 2 の当該規定を引く ISO 公開資料 |
| §2.5 | IRDI は登録機関識別子（ISO/IEC 6523 の ICD を含む）・データ識別子・版識別子の3部構成 | **支持** | ECLASS「IRDI」技術仕様、ISO/TS 29002-5 の概要 |
| §3.1 | RAMI 4.0 の Layers 軸は6層 | **支持** | DIN SPEC 91345 の目次、RAMI 4.0 の解説資料 |

ISO 19111 の言い換えはレビューの文中にしかなく、仕様書側（第2編 Clause 2）は「座標系と座標参照系の区別」と書いているため、仕様書の修正は要らない。
